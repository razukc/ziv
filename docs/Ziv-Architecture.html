Architecture

Honest frames baked into the diagram as notes

  • Always-on is the relay, not the device — the relay is the 24/7 presence (heartbeat + scheduled jobs); the wristband sleeps between events and wakes on button / chord / mic / WiFi activity.
  • Phone = dev band — the PWA is the visible output channel today; the wrist build is scoped / de-risked, not a flashed device yet.
  • Friend's side is text, not spoken — the friend reads the reply as text on their phone / relay log; there is no speaker in the room; spoken replies are v2 (TTS on the relay).
  • Refusals are loud and sender-visible — a full queue returns message:rejected (reason: queue_full); the server maps it to HTTP 429; the client shows "wrist is busy" and re-arms its own redial on the free: true close.
  • Wrist scope, not a claim — ESP32-S3 N16R8 + 6× DRV2605L + 6 LRAs + 6 chord keys + I2S mic + LiPo; QEMU ladder + bring-up stages A–F de-risk it, but it is not on hardware yet.
